# 消费密码后端核心设计

## 当前实现范围

本阶段已经实现消费密码领域服务，但不开放 H5 HTTP 接口。原因是消费者微信登录尚未完成，现阶段如果让前端直接提交 `customerId`，攻击者可能伪造其他消费者身份设置或修改密码。

已有能力：

- 查询当前消费者是否已设置消费密码，以及是否处于锁定状态。
- 首次设置消费密码。
- 使用原密码修改消费密码。
- 核销前校验消费密码。
- 连续输错计数及临时锁定。
- 设置、修改和触发锁定的安全审计。

## 密码策略

- 固定为 6 位数字，使用字符串传递，避免丢失开头的 `0`。
- 禁止全相同数字及明显连续数字，例如 `000000`、`123456`、`654321`。
- 使用项目统一的 BCrypt 编码器保存哈希，不保存明文，也不在日志或审计快照中保存密码和哈希。
- 默认连续输错 5 次后锁定 30 分钟。
- 锁定次数和时长可以通过环境变量调整：
  - `PLATFORM_CUSTOMER_PIN_MAX_FAILED_ATTEMPTS`
  - `PLATFORM_CUSTOMER_PIN_LOCK_DURATION`

## 数据库

V1 基线脚本已经包含 `t_customer_security`，本阶段不需要执行新 SQL。使用字段：

- `consume_pin_hash`
- `failed_count`
- `locked_until`
- `pin_updated_time`

## 事务边界

密码记录通过 `SELECT ... FOR UPDATE` 串行修改。密码校验和错误计数使用独立事务，确保核销失败或外层事务回滚时，错误次数及锁定状态仍然有效。

未来完成核销时应先调用密码校验服务；校验成功后再进入积分扣减事务。积分扣减仍需重新锁定积分账户并检查订单状态、有效期和余额，不能依赖创建待确认订单时的余额检查。

## 后续 H5 接口

等微信登录可以提供可信的消费者身份后，再开放：

```text
GET  /api/v1/h5/security/consume-pin/status
POST /api/v1/h5/security/consume-pin
PUT  /api/v1/h5/security/consume-pin
```

这些接口必须从登录凭证读取 `customerId`，请求体中不接受 `customerId`。

忘记密码功能后续采用“微信登录状态 + 绑定手机号验证码 + 一次性重置凭证”，并在重置成功后取消该消费者全部待确认消费订单。本阶段不接入短信服务商，也不提供店员或管理员代设密码接口。
