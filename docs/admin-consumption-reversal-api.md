# 消费异常冲正

本阶段实现已完成消费的异常冲正。它不是普通退款，只用于重复扣减、金额录入错误等需要恢复积分账务的异常场景。仅超级管理员可以操作，原因必填，不需要二次审核。

本阶段复用 V1 已有的消费冲正、积分批次和结算调整字段，不需要执行新的 Flyway 脚本。

## 接口

```http
POST /api/v1/admin/consumption-orders/{orderNo}/reversal
Authorization: Bearer <SUPER_ADMIN accessToken>
Idempotency-Key: <同一次重试保持不变，最长64位>
Content-Type: application/json

{
  "reason": "门店重复发起扣减，关联工单 CS-001"
}
```

成功后返回冲正流水号、客户和门店编号、退回积分、客户当前积分余额、结算处理状态及冲正时间。

## 账务规则

- 只允许冲正 `COMPLETED` 消费订单，同一订单只能成功冲正一次。
- 原消费实际使用了哪些充值批次，冲正就把积分逐笔退回相同批次，不新建来源不明的积分。
- 增加客户积分账户余额，并写入 `REVERSAL + CONSUMPTION_ORDER` 正向积分流水。
- 原消费订单改为 `REVERSED`，保存超级管理员、时间和必填原因。
- 充值批次即使在消费冲正后恢复积分，也仍视为发生过消费，不能再走“未消费充值全额退款”。
- 冲正只恢复平台积分，不会自动向客户退现金。

## 结算处理

- 原消费尚未进入结算单：直接标记为已处理，不产生门店应付款。
- 原消费已进入未结清结算单：历史结算单保持不变；该结算单结清后，冲正在后续月份形成负数调整。
- 原消费已经结算：在后续月结中生成 `REVERSAL_ADJUSTMENT` 负数明细，冲减消费额、平台手续费和门店应结金额。
- 月结生成会补抓结算期结束前尚未处理的历史冲正，成功计入后把原订单结算状态改为 `ADJUSTED`，避免重复调整。
- 如果当月负数调整大于正向消费，结算净额可以为负，表示门店应向平台退回款项；净额为零时无需实际收付款，但仍需登记结清参考号。

## 幂等与并发

- 相同 `Idempotency-Key`、订单、操作员和原因会返回第一次成功结果，不会重复退回积分。
- 同一幂等键用于不同请求会返回幂等冲突。
- 冲正与客户消费确认、月结生成并发时通过积分账户锁和消费订单锁串行处理。
- 任意积分批次、流水、订单或审计记录写入失败，整个事务回滚。
