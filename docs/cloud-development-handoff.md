# 积分平台项目交接与云端协作

记录日期：2026-10-12（北京时间）。本摘要根据当前源码、Git 状态和部署文档整理；本次没有执行构建测试，也没有连接服务器核实线上状态。

## 已确定的协作方式

用户选择：**云端阅读和修改代码，本地运行与验收，Git 同步代码，同一个云端任务接续讨论。**

- 云端负责代码分析、实现和必要的定向测试、类型或构建检查；按当前任务准备工具，不默认搭建完整云端 MySQL/Redis 或迁移现有服务器。
- 用户在公司或家里的电脑运行后端、MySQL、Redis 和两端前端，用浏览器、手机及调试工具验收。
- 云端改动提交并推送到约定分支后，本地才能拉取；用户本地修复也应推送并告知提交，再让云端同步。Git 不同步聊天、本地配置、凭证和数据库。
- 本地反馈包含仓库、分支、提交、平台、复现步骤、预期与实际结果及关键报错。已有云端任务不能假定自动包含新推送的本地提交。
- 当前本地聊天不会通过 Git 转成云端聊天；新云端任务先读本摘要和各仓库 AGENTS.md 接续背景。
- 本次只整理文档，提交推送由用户完成，未操作远端仓库或现有服务器。

三个根目录 AGENTS.md 已生成，分别包含各自技术栈、代码路径、检查命令、业务约束及跨仓库协作说明；当前文件保存有日期的项目情况，后续交接补充日期、配套提交和验证结果。

## 项目要点

项目由旧商城逐步重构为多门店通用积分平台。业务主线为：平台收款 → 员工登记充值 → 客户获得通用积分 → 员工创建待确认消费 → 客户在自己的设备输入消费密码确认 → 扣减积分 → 门店自然月结算。

- 固定 1 元 = 1 积分，整元充值，积分不过期；充值款进入平台账户，门店不代收。
- 积分按充值批次管理，消费先进先出；账户、订单、流水更新依靠数据库事务、行锁和幂等机制。
- 从未被消费过的充值订单可以整笔退款，不支持部分充值退款。
- V1 不提供普通消费退款；异常操作由超级管理员执行有审计记录的冲正。
- 平台手续费默认 5%，可调整；订单保存费率快照，调整不重算已有订单。
- 后台按角色及员工门店范围控制权限。
- 微信支付、营销赠送积分、自动银行付款不属于当前 V1 能力。

详细规则以后端 docs/v1-domain-design.md 和各接口文档为准。

## 同步与接续步骤

1. 分别审查三个仓库的差异，确认当前预发布源代码、部署文档、AGENTS.md 和本摘要一并同步。公开前端配置的 .env.staging 可以提交；真实后端 .env、backend.env、私钥、数据库备份、upload、JAR、ZIP、dist、node_modules 单独处理。
2. 每个仓库独立提交并推送到自己的 origin，记录一组配套的三仓库提交 SHA。上层工作目录不是总仓库，不能承担三个仓库的提交。
3. 家里分别克隆或同步三个仓库到约定分支，核对提交，按锁文件安装依赖并填写本地开发配置；三个仓库无需先合并。
4. 建立包含三个仓库的 Codex 云端环境，先准备阅读、编辑代码和当前任务必要的工具；完整业务运行和数据验收继续在本地完成。
5. 在同一个云端任务讨论需求，审查代码后通过 Git 同步到本地运行。测试失败时反馈明确的版本和复现步骤，云端修复后再次同步。
6. 本地自己改动也要提交推送，再让云端同步对应分支和提交，避免两端同时覆盖同一文件。重要代码保存到 Git，不依赖单个云端任务的工作副本。

交接格式：完成项、各仓库分支/提交、实际验证结果、未验证项、待办及下一步。不附明文凭证或整个数据库。完成一项线上验收时补充日期和环境，不把候选包构建成功当作发布完成。

## 环境与数据注意点

- 管理端 Node 要求 ^22.18.0 || ^24.0.0，固定 pnpm@10.33.4；消费者端使用 npm 和 package-lock.json。
- 当前本地后端面向 MySQL 5.7，服务器是 MySQL 8.4；Maven -Pserver 选择服务器驱动。本地需明确数据库版本和 profile；云端代码任务默认不运行完整业务数据库。
- deploy/compose.yml 只部署后端，依赖已准备的镜像、upload 目录及外部数据库/Redis Docker 网络；它不是完整开发环境编排。
- 新开发空库由 Flyway 初始化，当前实际迁移为 V1～V6。旧数据库管理文档只列到 V4，应以迁移目录为准；已执行的迁移脚本不可修改。
- Spring prod 配置用于服务器安全配置，当前账本仍是预发布测试数据，不能直接转为正式财务账本。本地验收使用独立开发数据；云端只取得当前任务必要的模拟数据。
- JWT、微信 AppSecret、短信 AccessKey 和数据库密码只属于后端配置，不能写入 VITE_ 变量；前端构建配置会进入浏览器产物。
- 微信授权、短信和手机内验收仍需要相应凭证、回调域名及人工联调，构建成功不能替代。
- 家里可参考管理端 apps/web-antd/README.private-backend.md 配置 SSH 隧道继续预发布联调；SSH 身份和访问条件需单独配置。

## 迁移后的检查命令

以下是代码修改后的建议检查，不是本次执行结果。每组在对应仓库根目录运行；纯文档改动只检查内容、路径和 Git 差异。

~~~bash
# 后端，Java 21
./mvnw test
# 独立本地开发环境已配置时启动
./mvnw spring-boot:run
# 面向服务器 MySQL 8.4 的构建
./mvnw -Pserver test package

# 管理端
pnpm install --frozen-lockfile
pnpm dev:antd
pnpm --filter @vben/web-antd typecheck
pnpm build:antd:staging

# 消费者端
npm ci
npm run dev:h5
npm run check
npm run build:h5:staging
~~~

Windows 后端使用 .\mvnw.cmd。管理端开发为 pnpm dev:antd，消费者 H5 开发为 npm run dev:h5。

验收包含三端检查/构建、后端健康检查、后台登录与门店权限、H5 账户与积分查询，以及独立开发数据上的充值 → 客户确认消费 → 流水核对；之后再验证整笔退款和月结。
